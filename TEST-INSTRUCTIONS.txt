JARVIS OS V24 RELEASE CANDIDATE - LOCAL TEST

1. Make sure Python, Node.js, Git, and (for local AI) Ollama are available.
2. Keep your real secrets only in .env. Do not copy runtime data or token keys into Git.
3. Install gateway dependencies:
     python -m pip install -r api-gateway/requirements.txt pytest
4. Run the release verification stack from the repository root:
     python -m compileall -q api-gateway tests
     python -m pytest -q
     node --test tests/voice-engine.test.js
     python tools/generate_repo_reports.py --check
5. Start Jarvis with START-LOCAL-TEST.bat or:
     python -m uvicorn main:app --app-dir api-gateway --host 127.0.0.1 --port 8000
6. Check:
     Dashboard: http://127.0.0.1:8000/dashboard
     Voice:     http://127.0.0.1:8000/voice-live
     API Docs:  http://127.0.0.1:8000/docs
     Liveness:  http://127.0.0.1:8000/health
     Readiness: http://127.0.0.1:8000/ready
7. Readiness may return 503 when no intelligence provider is configured/online; that is expected.
8. If AI_REQUIRE_AUTH=true, use the dashboard API Session control for authenticated requests.
9. Validate Docker on the target Windows machine before production deployment:
     docker compose config
     docker compose up -d --build
10. Test configured live integrations (Gemini/OpenAI/Deepgram/Google OAuth/Host Bridge/Home Assistant) on the target host; offline CI intentionally mocks or skips real credentials.

Expected release-candidate automated baseline at packaging time:
- 145 Python tests passing
- 19 Node voice tests passing
- Python compileall passing
- generated report drift check passing
