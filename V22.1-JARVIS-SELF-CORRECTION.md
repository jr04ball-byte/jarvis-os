# Jarvis V22.1 — Self-Correcting Project Worker

V22.1 hardens the V22 Project Worker into a bounded, resumable diagnose → implement → verify → repair loop.

## Added

- Workspace baselines that fingerprint repository files before autonomous work.
- Separation of pre-existing user changes from files changed during the worker run.
- Targeted Python verification when a corresponding test file can be identified.
- Durable Project Worker run state in `data/project_worker.db`.
- Resumable worker runs through a run ID.
- Failure-evidence repair prompts that feed actual exit codes/stdout/stderr back to OpenCode.
- Bounded retries (`0..4`, default `2`) rather than infinite repair loops.
- `/v1/project-worker/autofix` for bounded self-correction.
- `/v1/project-worker/runs/{run_id}` for durable run inspection/resume support.

## Safety boundaries retained

- OpenCode remains scoped to the registered workspace.
- `.env`, private keys, credential files, deployments, publishing, commits, destructive Git operations, and external side effects remain outside the worker's autonomous authority.
- Existing user changes are captured before work and reported separately.
- Jarvis blocks after the retry budget is exhausted instead of looping indefinitely or claiming success.

## Flow

`baseline → inspect → OpenCode implement → detect worker delta → targeted verification → repair from evidence → re-verify → verified OR blocked`

## Notes

The baseline system identifies files whose contents changed during the run. If the worker must modify a file that already had uncommitted user edits, V22.1 flags that overlap explicitly in `overlap_with_preexisting` so Jarvis can surface it rather than silently treating the entire diff as worker-owned.
